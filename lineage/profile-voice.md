## Brandon Freeman

Worldbuilder. Most of the rest of this came out of that.

Keep a world going long enough and you hit the boring problems. Two notes
disagree. A name starts meaning two things. Somebody changed a rule and nobody
wrote down that they did. Fixing that is metadata, taxonomy, versioning and
access control — which is also, it turns out, nine years of my day job.

So most of what follows is one question in different clothes. When a claim
carries the evidence for it, two parties can hold the same state instead of each
keeping a copy with a separate account of it, and they end up in one frame rather
than two. That works between people. Whether it works between a person and a
model is what I'm actually testing.

**Records.** {soveraeign} is the long version: people and models working through
the same records, permissions and history, neither getting a private door.
{ontum} points the same instinct at autonomous work, where an append-only log is
the truth and every other view is folded from it. It grew out of {onton},
archived now, which typed how an artifact was made so that trust survived being
handed on.

**Making.** {schematically} treats a schematic as a semantic model of components,
parts and wires rather than a drawing, and writes it in Soveraeign's document
format. It superseded {canvas}, which was the same idea about arranging things in
space. {ide} is a small editor that opens in a chat side panel.

**Working with models.** Most of this is harness work — the skills, roles and
rules a model runs under. {familiar} is a workbench for agent guidance that a
practitioner has to accept before it binds. It uses {owl}, which turns a rough
ask into a complete inspectable attempt and then redraws that same target from
feedback instead of wandering onto a different one. {howdo} is the discipline
under both. {context} hands an agent a bounded world in a single file;
{system-cartographer} goes the other way, recovering the description of an agent
system nobody wrote down. {ddd-ccc} asks how much of a repository's meaning its
tests actually reach, and names the gaps.

I do this at work too: a workflow engine with retrieval over company knowledge,
running multi-step jobs with a person at every decision point — a state machine
rather than an open-ended agent, so every step can be audited and rewound. That
one you can't check from here.

**Fun.** {small-world} is a lab for generative worlds. {nostalgia} gets old games
running and playable with friends again. Those aren't the side quests.

All of it is checked, and {lineage} is where the checking lives: the command for
each repository and what it returned, how they relate with the file and line that
shows it, and the ones that connect to nothing at all.
